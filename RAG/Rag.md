RAG Architecture Description
The SACCO Member-Case Preparation Agent will use a Retrieval-Augmented Generation (RAG) architecture to provide responses based on a controlled and traceable knowledge source. The purpose of the RAG architecture is to reduce the reliance on the foundation model's pretrained knowledge by retrieving relevant information from approved SACCO policy documents and procedures before generating a response.
1. Controlled Knowledge Corpus
The RAG system will use a controlled corpus containing SACCO-related documents relevant to the Loans Department. The corpus may include loan policies, loan application procedures, loan requirements, repayment procedures, collateral guidelines, credit committee procedures, and other approved operating guidelines.
Each document will be associated with provenance information such as the document title, document type, version, date, source, and relevant section. This ensures that information retrieved by the agent can be traced back to its original source.
2. Document Ingestion
The document ingestion component is responsible for importing the controlled documents into the RAG system. Documents such as PDF, DOCX, TXT will be processed and converted into machine readable text.
During ingestion, unnecessary formatting and other irrelevant content will be cleaned while important document metadata will be preserved. The resulting text will then be passed to the chunking component.
3. Document Chunking
Large documents will be divided into smaller meaningful sections known as chunks. Chunking allows the retrieval system to identify specific sections of a policy that are relevant to a user's question instead of processing an entire document.
Where possible, chunks will preserve the document's section information and metadata. For example, a chunk may contain the policy name, section number, topic, version, and source document.
4. Embedding Generation
Each document chunk will be converted into a numerical vector representation using an embedding model. The embedding represents the semantic meaning of the text and allows the retrieval system to identify content that is relevant to a user's question.
The generated embeddings will be stored together with the original text and associated metadata.
5. Vector Database
The vector database will store the embeddings and their corresponding document information. It will support semantic similarity searches when the agent receives a question from a loan officer.
The database will maintain information such as the document ID, chunk ID, text content, embedding vector, document section, version, and source. This metadata will allow retrieved information to be traced back to the original policy document.
6. Query Processing and Retrieval
When a loan officer submits a question or requests assistance with a loan case, the question will be processed and converted into an embedding. The retrieval component will compare the query embedding with the embeddings stored in the vector database.
The system will then retrieve the most relevant policy chunks and provide them as evidence for the agent.
For example, when a loan officer asks, "What documents are required for a development loan?", the retrieval component will search the knowledge base and return the relevant sections of the development loan policy and associated procedures.
7. Context Construction
The retrieved policy evidence will be combined with the user's question and the instructions governing the Member-Case Preparation Agent. This creates a context that is provided to the foundation model.
The constructed context will contain the information necessary for the model to generate a grounded response. The agent will be instructed to base its response on the retrieved evidence and avoid inventing information that is not supported by the available sources.
8. Foundation Model
The foundation model will process the user's question together with the retrieved policy evidence and agent instructions. It will use the retrieved information to generate a natural-language response that is relevant to the loan officer's request.
The foundation model will therefore function primarily as the reasoning and response-generation component, while the RAG system provides the controlled knowledge used to ground the response.
9. Grounded Response and Source Attribution
The final response generated by the agent will contain information derived from the retrieved evidence. Where applicable, the response will identify the source document, section or other provenance information used to generate the answer.
This provides traceability and allows loan officers to verify the information against the original SACCO policy.
10. Handling Unanswerable Questions
The RAG architecture will also support safe handling of questions for which sufficient evidence cannot be retrieved. If the knowledge base does not contain enough information to answer a question, the agent will indicate that the information is unavailable rather than generating an unsupported answer.
This is important for preventing the agent from presenting invented SACCO policies or requirements as factual information.
11. Overall RAG Flow
The RAG architecture follows two main processes.
Knowledge preparation process:
Controlled SACCO Documents → Ingestion → Cleaning → Chunking → Embedding Generation → Vector Database
Question-answering process:
Loan Officer Question → Query Processing → Retrieval → Relevant Policy Evidence → Context Construction → Foundation Model → Grounded Response + Sources
